# repair15：原版游戏侧栏启动适配

用户报告：权限正常，从游戏空间启动已添加游戏，白条和滑出面板均未出现。没有手机日志，因此以下为代码中确认的问题与修复，不能证明设备上的全部原因。

## 改动

- 从原游戏空间启动游戏前显式启动 DockWindowManagerService；在游戏空间恢复和原设置保存时也检查启动。服务使用 Android 前台服务通知保持监测，官方 Shizuku 在 :ui 进程识别真实前台包名。数据库核对包名、UID 和 is_del=0；退出游戏、锁屏、失联或监测过期时移除窗口。
- 替换服务的小米私有初始化后端，保留 s8.h、原 SidebarWrapper、白条 Drawable、手势回调、TurboLayout 和 FrameRateView。主白条触摸窗口采用 TYPE_APPLICATION_OVERLAY，允许接收触摸；屏幕旋转后重新创建。移除前及时清理原定时任务和已挂载的部分窗口。
- 原 RegionSamplingImageView 不再创建需要系统权限的 RegionSamplingHelper；保留原白条绘制与触摸。
- 原 s8.h 在窗口挂载时 R0 写入 Settings.Secure.sidebar_bounds，滑动回调 U0 写入 Settings.Global。悬浮窗授权不能授予这些写权限；改为原 RemoteProvider 支持的应用内存储，避免 SecurityException。清理也使用同一存储，不修改设备系统设置。
- 保留 gs_setting.xml 原有设置树，绕过小米机型限制对条目的隐藏/删除。游戏空间、游戏工具箱及滑动入口开关仍读取原存储键，已有关闭状态不会被强制开启。仅小米设备支持且未适配的条目保留显示并标注“当前设备暂不支持”，不声称它们可用。
- 添加白条左右侧、高度（25/50/75%）和向内偏移（0/16/24/40dp）。默认左侧、25% 高度、24dp 向内偏移；保持原滑出面板。设置和状态通过 RemoteProvider 在进程间共享。
- Shizuku 页面展示侧栏状态并提供启动监测按钮。定位启动失败、前台识别失败、未添加应用、设置关闭或窗口创建失败；异常进入已有崩溃日志。
- 修复构建脚本残留匿名内部类问题，仅清理自身 Java 生成的类，不删除原兼容类。

## 验证

`bash scripts/test.sh`：12 项真实帧解析、6 项前台解析、5 项生产 shell 模拟、10 项白条位置边界用例通过。静态检查原方法/字段的反射契约、设置资源保留、服务接线及挂载/手势路径无 Secure/Global 写调用。

`bash scripts/build.sh`：重编译 Java、D8、smali、资源和完整 APK。签名验证文件与 APK SHA-256 位于 releases/。签名沿用本会话上次新密钥，版本号 40001054，版本名 10.4.5-huawei-repair15-sidebar。

## 设备验证仍需完成

当前没有华为手机或 Android 模拟器，未进行安装、白条显示、滑出、旋转或 FPS 实测。构建与静态检查不能证明原版所有未触达路径在 HarmonyOS 上可运行，也不能证明华为侧边小窗一定冲突或已完全解决。
